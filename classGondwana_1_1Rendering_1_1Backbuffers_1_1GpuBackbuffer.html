Detailed Description

Provides a fully GPU-rendered backbuffer implementation using SkiaSharp and OpenGL.

Architecture (GL-thread rendering): All rendering operations (tile drawing, canvas operations) and presentation happen on the GL thread, driven by WinFormGpuRenderSurfaceAdapter from within SKGLControl.PaintSurface. The engine's background loop skips this surface entirely (see IsGlThreadRendered). No CPU↔GPU data transfer occurs for the backbuffer contents; tiles are rasterised directly into an off-screen GPU render target and then blitted to the window surface in a single GPU draw call.

Before the first Initialize call the backbuffer uses a temporary CPU raster surface (identical to BitmapBackbuffer) so that the host can always be in a valid state. Once a GRContext becomes available on the GL thread, Initialize replaces that with a proper GPU surface.

Thread safety: After Initialize has been called, all methods and properties that access or mutate GL state must be invoked from the GL thread (the thread on which the GRContext is current). The engine loop guarantees this by checking IsGlThreadRendered before touching the backbuffer. The simple configuration properties VSync, MsaaSampleCount, and TargetFps are exempt from this restriction: they only write to plain fields and may be set from any thread (for example, from Gondwana.Configuration.EngineConfiguration setters running on the engine background thread).

◆ MsaaSampleCount

int Gondwana.Rendering.Backbuffers.GpuBackbuffer.MsaaSampleCount
getset

Gets or sets the number of MSAA (multisample anti-aliasing) samples used when creating the GPU render-target surface.

This property only applies to GpuBackbuffer; other backbuffer types ignore it.

This value is kept in sync with Gondwana.Configuration.EngineConfiguration.MsaaSampleCount (which propagates its value to all registered GPU backbuffers). A value of 1 disables MSAA. Common values are 2, 4, or 8, subject to hardware support.

Changing this property on an already-initialized backbuffer takes effect the next time Initialize is called (e.g. on the next window resize), because the GPU render-target surface must be recreated with the new sample count.

If the requested sample count is not supported by the hardware or driver, Initialize will automatically fall back to a sample count of 1 (no MSAA) so the surface is always valid.

The MSAA sample count. Values less than 1 are clamped to 1. The default is 1.

int Gondwana.Rendering.Backbuffers.GpuBackbuffer.TargetFps

Gets or sets the target frame rate associated with this GPU backbuffer.

This value is kept in sync with Gondwana.Configuration.EngineConfiguration.TargetFPS (which propagates its value to all registered GPU backbuffers). The engine's own foreground cycle — not the backbuffer — is responsible for throttling the frame rate; see Gondwana.Configuration.EngineConfiguration.TargetFPS for details.

The desired frames per second. Negative values are clamped to zero. The default is 60.

◆ VSync

bool Gondwana.Rendering.Backbuffers.GpuBackbuffer.VSync = true
getset

Gets or sets a value indicating whether vertical synchronisation (vsync) is enabled.

This property only applies to GpuBackbuffer; other backbuffer types ignore it.

This value is kept in sync with Gondwana.Configuration.EngineConfiguration.VSync (which propagates its value to all registered GPU backbuffers). The value is read by the platform adapter (e.g. WinFormGpuRenderSurfaceAdapter) at the start of each PaintSurface call and applied to the underlying GLControl.VSync property when it changes. Enabling vsync prevents screen tearing but caps the frame rate to the monitor refresh rate. Disabling vsync allows higher frame rates at the cost of potential tearing.

true to synchronise presentation with the monitor refresh; otherwise false. The default is true.
